### Out of scope

- Automatically merging or modifying release PR `#52` (`chore(release): publish v0.2.0`), or modifying GitHub repository secrets or variables.
- Publishing `packages/core`, `apps/api`, or `apps/web` to npm (`Q2.A` keeps `apps/cli` as the sole published npm package).
- Introducing a custom `scripts/release_please.cjs` plugin (`D-021(1)` keeps stock `googleapis/release-please-action`).
- Adding new `P14` audit-triage or multi-ref pre-push hook hardening work.

### Decisions

- **Q2.A (Unpause `D-045` for `apps/cli` only):** Re-enable `push: tags: ['v*']` alongside `workflow_dispatch:` on `.github/workflows/publish.yml` for `apps/cli` (`ts-launch-blueprint`), keeping `packages/core` private and bundled and keeping `concurrency.cancel-in-progress: false`.
- **Q11.C (`.oss-scanner/` + `.github/SECURITY.md`):** Ship `.oss-scanner/{Dockerfile,threat_model.md}` as blueprint-only security artifacts removed on `press rebrand` via `[[remove]]` rules in `press/press-rules.toml`, paired with upgraded `.github/SECURITY.md` and `press/stubs/security.md`.
- **Default (`D-021(1)`):** Keep stock `googleapis/release-please-action` without custom commit-selection scripts.
- **Tag policy on `npm` environment:** `scripts/setup-github-environments.sh` configures `type=tag` (`v*`) on `npm` (matching `publish.yml` tag deployments) and `type=branch` (`main`, `release/*`) on `security-review`.
- **Press-safe retained docs:** Retained `docs/adr/*`, `docs/about/design-decisions.md`, `docs/PROJECT_SETUP.md`, and `docs/RELEASE.md` never link to template-only `docs/port/` or `projects/` so `just docs-check` passes in pressed child repositories as well as the blueprint.
