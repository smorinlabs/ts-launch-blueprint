# Project Structure

TS Launch Blueprint follows the standard npm/TypeScript layout: a
single `src/` tree bundled by tsdown into `dist/`, tests alongside it
in `tests/`, and documentation in `docs/`. This section walks through
the actual directory layout and the purpose of each file.

## Directory Layout

```
ts-launch-blueprint/
├── src/                            # Source code (TypeScript)
├── tests/                          # Vitest test suites
├── dist/                           # Build output (generated by tsdown; not tracked)
├── docs/                           # Documentation (this tree)
├── .github/                        # GitHub Actions workflows, issue/PR templates
├── Justfile                        # Command surface (build/test/lint/release/...)
├── Makefile                        # Bootstrap: check-deps / install-node / install-just
└── package.json                    # npm manifest (scripts, dependencies, bin, exports)
```

## Directory Descriptions

### `src/`

The CLI's source code. `cli.ts` is the thin process entry point;
`router.ts` builds the Commander program and owns the exit-code
mapping; `commands/projects.ts` implements the default `projects`
command; `lib/` holds the pure/injectable building blocks (API client,
config resolution, formatting, logging, color gating, XDG paths, and
the terminal I/O adapters). `lib.ts` re-exports the subset of this
surface meant for consumers who import the package as a library rather
than run its binary.

### `tests/`

Vitest suites. Most files are in-process unit tests that inject fakes
via the `CliDeps` dependency-injection surface; `e2e.test.ts` runs the
built `dist/cli.js` as a real subprocess; `repo-hygiene.test.ts` is a
meta-test tier asserting the repo's own configuration files stay
internally consistent (e.g. commit-type lists, ignore-pattern mirrors).

### `dist/`

Generated by `just build` (`tsdown`); never tracked in git. Contains
the bundled `cli.js` (the `ts-projects` executable) and `lib.js`/
`lib.d.ts` (the importable library), plus source maps.

### `docs/`

All documentation, as plain CommonMark/GFM (no Sphinx, no MyST — see
[Docs About Docs](../docs.md)).

### `.github/`

GitHub Actions workflows (CI, CodeQL, dependency review, release-please,
publish) and community files (issue templates, PR template,
CODE_OF_CONDUCT, CONTRIBUTING, SECURITY, dependabot, FUNDING).

### `Justfile`

The command runner surface — build, test, lint, format, typecheck,
release, and packaging recipes. See
[Using the Justfile](../tools/justfiles.md).

### `Makefile`

Dependency bootstrap only (`make check`, `make install-node`, `make
install-just`) — not a build system. See
[Using Makefiles](../tools/makefiles.md).

### `package.json`

The npm manifest: name, version (owned by release-please — see
[Versioning](./versioning.md)), the `ts-projects` bin entry, the ESM
`exports` map, scripts, and dependencies. See
[Configuration Files](./configuration-files.md).

### `tsconfig.json`, `.oxlintrc.json`, `.oxfmtrc.json`, `vitest.config.ts`, `tsdown.config.ts`

Tool-specific configuration for the typecheck, lint, format, test, and
build gates respectively. Each is documented in
[Configuration Files](./configuration-files.md) and has a companion
page under [`docs/tools/`](../tools/).

### `lefthook.yml`, `commitlint.config.mjs`

Git-hooks and commit-message enforcement. See
[Configuration Files](./configuration-files.md) and
[Lefthook](../tools/lefthook.md).

### `release-please-config.json`, `.release-please-manifest.json`, `CHANGELOG.md`

The release pipeline's configuration and generated output. See
[Versioning and Release Management](./versioning.md).

### `EXAMPLECLI.md`

The full UX specification for the `ts-projects` example CLI: every
flag, the config-file precedence, environment variables, and the
exit-code mapping. See also [CLI Reference](./cli-reference.md).

### `README.md`

The project overview and navigation hub for the documentation tree.
